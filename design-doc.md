# Design Doc — Telegram-бот для изучения английских слов

## 1. Обзор

Персональный (пока) Telegram-бот для пополнения и тренировки англо-русского
словаря по принципу интервального повторения (SRS). Три активности:

- **Добавление** слов (русских или английских) — режим по умолчанию.
- **Повторение** — пассивная тренировка узнавания, по расписанию или по кнопке.
- **Тестирование** — активная проверка (печатаешь перевод), по кнопке.

Изучение всегда в направлении **RU→EN** (показываем русское, ждём/проверяем
английское), независимо от того, на каком языке слово добавили.

## 2. Стек и ключевые решения

- **Node.js + PostgreSQL.**
- **Telegram-библиотека: grammY** — TS-first; плагины *conversations* (пошаговый
  флоу добавления слова) и *sessions* (FSM-состояние пользователя).
- **Перевод: Yandex Dictionary API** — авторитетный курируемый словарь (смыслы,
  часть речи, синонимы). НЕ LLM.
- **Генерация примера и фоллбэк для редких слов: LLM через Vercel AI SDK**
  (`ai` + `@ai-sdk/groq`). Провайдер переключается через env `LLM_PROVIDER`
  (сейчас **Groq**, модель `openai/gpt-oss-120b` — бесплатно/без карты, есть
  structured output). Structured JSON — `generateObject` + zod-схема. Добавить
  openai/anthropic/mistral = ветка в фабрике модели (`services/llm/model.ts`) + ключ.
- Источник перевода и LLM — **за интерфейсами** (`LlmProvider`/`DictionaryProvider`),
  чтобы менять провайдера без переписывания.
- **Планировщик: собственный (cron).** Нативной отправки «в 9:00» у Telegram нет
  — бот сам шлёт `sendMessage`. Бот не может написать первым тому, кто не нажал
  Start → сохраняем `chat_id` на `/start`. Учитываем лимит ~1 сообщение/сек на чат.
- **Мультитенантность: схема с первого дня** (`user_id` во всех таблицах, все
  запросы фильтруют по нему), **но фичи мультиюзера не строим** — пока whitelist
  своего `chat_id`, без онбординга. Появится второй юзер — снять whitelist +
  добавить онбординг, без миграций.
- **Провижининг на `/start`:** идемпотентно создаём строку `users` + дефолтные
  `settings` (на них висят FK у `words`). `OWNER_CHAT_ID` валидируется как целое
  на старте — иначе whitelist молча заблокирует всех, включая владельца.
- **Надёжность процесса:** `bot.catch` для контролируемого лога ошибок (стабы
  кидают `not implemented`), `pool.on('error')` на пуле PG, graceful shutdown по
  SIGINT/SIGTERM (`bot.stop()` + `pool.end()` + остановка cron).
- **Прод-деплой: Docker-образ + long polling (решено).** Образ собирается в GitHub
  CI → GHCR (private) → Coolify на VPS тянет его и перезапускает по деплой-вебхуку
  (конвенции — `infra/deploy-playbook.md`). **Telegram-вебхук НЕ используем**: при
  одном пользователе long polling даёт нулевую входящую поверхность — боту не нужны
  ни домен, ни DNS, ни открытый порт вообще; пересмотреть при мультиюзере. Сборка —
  tsup-бандл СВОЕГО кода (ESM с extensionless-импортами не запускается из голого
  tsc-emit), зависимости — внешние, в образе как pruned `node_modules` (полный бандл
  ломал рантайм-инварианты deps; см. tsup.config.ts). **Миграции применяются на
  старте контейнера** (программный мигратор drizzle-orm, `src/migrate.ts`,
  fail-fast в entrypoint) — бот не стартует на неприменённой схеме. Liveness —
  `/healthz` на localhost (`src/health.ts`) под Docker HEALTHCHECK: 200 только
  когда поллинг реально запущен. Non-root (`node`), `exec` в entrypoint → PID 1 =
  node, SIGTERM доходит до graceful shutdown.

## 3. Принцип использования LLM

> **LLM — только там, где её ошибка дёшева и заметна пользователю. Авторитетный
> API — там, где ошибка молчаливая и вредная.**

- **Перевод** — молчаливый (учишь слово, не можешь проверить) + вредный
  (зазубришь неверное) → **словарь, не LLM**.
- **Пример** — виден и проверяем (зная перевод) + низкий вред → **LLM**.
- **Грейдинг теста** — крутится без присмотра → **детерминированный, без LLM**.

## 4. Флоу: добавление слова

Режим по умолчанию (IDLE). Пользователь присылает слово.

1. **Определение языка по алфавиту:** кириллица → русское, латиница →
   английское. Без LLM/детектора.
2. **Перевод через Yandex Dictionary** в нужном направлении (`ru-en` / `en-ru`).
   **Двухстадийный поиск:** сначала по точной введённой форме (без флагов) — для
   словарных форм (дом, крыло) чистые списки смыслов; если пусто — повтор с флагом
   `MORPHO` (поиск по лемме), который вытаскивает словоформы (продолжаем → продолжать
   → continue, идём → идти → go) перед фоллбэком на LLM. MORPHO только как фоллбэк:
   на точных совпадениях он подмешивает чужие леммы (крыло → «крыть»=cover, дом →
   нареч. «дома»=at home).
   Смысл = один `tr` (НЕ `def`: те группируют по части речи). Все `tr` со всех
   `def` сводим в плоский список, отсекаем низкорелевантный хвост по `tr.fr`
   (страховка: если все низкие — оставляем все). Каждый смысл = ОДИН перевод
   (`tr.text`); синонимы `tr.syn` НЕ берём — у карточки один ответ.
   - **один смысл → сохраняем сразу;**
   - **несколько смыслов → выбор:** варианты с русским глоссом (`tr.mean`)
     перечисляем в ТЕКСТЕ сообщения, кнопки — номера (длинный текст кнопки Telegram
     режет).
   - **Карточка всегда RU→EN.** По направлению ввода:
     - **RU-ввод:** промпт = введённое слово; ответ = перевод выбранного смысла.
     - **EN-ввод:** ответ = введённое слово; промпт = русский перевод смысла.
3. **Фоллбэк для редких слов** (нет в словаре даже с MORPHO): LLM одним вызовом
   отдаёт перевод + пример; при добавлении показываем пометку **«Переведено с
   помощью LLM, проверь»**, дальше слово обычное (тестируется наравне со всеми).
   Пометка «fallback» — флоу-онли маркер (нудж проверить догадку LLM ДО сохранения);
   провенанс намеренно не хранится в БД (после сохранения карточка уже подтверждена
   юзером, а пост-сейв это поле никто не читал — см. §11).
4. **Пример через LLM:** кормим LLM выбранным переводом, получаем одно русское
   предложение со словом + его английский перевод (всегда формат RU→EN).
5. **Ответ-подтверждение** показывает карточку (слово → перевод, пример) с
   действиями: **«Другой пример»** (перегенерировать пример), **«Свой перевод»**
   (переопределить перевод своим — для ЛЮБОЙ карточки: словарной, фоллбэк или уже
   переопределённой; вводишь свой вариант → пример перегенерируется под него, а
   пометка «проверь» снимается) и **«Свой пример»** (своё русское предложение-
   контекст; английская половина — КОНСТРЕЙНД-перевод LLM, обязанный использовать
   `english` карточки: свободный MT мог бы перефразировать само учимое слово —
   ровно это делает Яндекс.Переводчик с редкими словами. Перевод заданного текста —
   констрейнд-задача, в отличие от свободной генерации примера, где LLM без
   контекста может промахнуться). Словарный перевод авторитетен по умолчанию, но
   при желании переопределяется явной кнопкой; омограф закрыт выбором смысла
   (шаг 2), полноценная правка карточки — в §10. Дубль по русскому промпту
   помечается («возможно, уже есть: …»).
6. Сохранение в БД, `next_review = завтра`. То же сообщение редактируется в
   сохранённую карточку с **✅ перед словом** (без отдельной строки «Сохранено»/id,
   без кнопок — это и есть сигнал «сохранено»; to-do §UX).

**Концептуально:** каждый перевод Yandex (`tr`) — отдельный выбор-карточка
(замок: castle / lock; и даже дом: house / home — Yandex отдаёт их разными `tr`).
Синонимы (`tr.syn`) в ответ не идут — карточка = один перевод. Принимать несколько
вариантов = ручная правка карточки позже (§10).

## 5. Флоу: повторение

- **Запуск:** по расписанию (планировщик шлёт напоминание «🔔 Регулярное
  повторение: N слов» с кнопкой **«Начать»** — тап раскрывает первую карточку в
  ТОМ ЖЕ сообщении) ИЛИ командой `/repeat` (тогда сегодняшнее плановое
  пропускается). И планировщик, и `/repeat` зовут один и тот же `startReview` —
  выборка и поведение идентичны, разницы нет: планировщик решает лишь «пора ли по
  времени и не запускали ли уже сегодня», а ЧТО повторять — целиком дело
  `startReview` (N слов с наименьшим `next_review`, без due-гейта). Напоминание
  через кнопку (а не сразу карточкой) выбрано намеренно: тап идёт через обычный
  middleware и получает настоящую сессию, поэтому планировщику не нужно
  инъектировать состояние сессии извне. Побочный плюс — оно не перебивает activный
  тест: это просто сообщение с кнопкой, а `startReview` сам не даст начать, пока
  тест не закрыт (Фаза 7 «отложить плановое во время теста» почти отпадает).
- **Повторение ВСЕГДА доступно.** Нет условия «due» (`next_review <= today`) — оно
  бессмысленно для выборки. В сессию берём N слов с **наименьшим `next_review`**
  (самые «созревшие» первыми), N = `min(review_count, размер колоды)`. Пусто только
  если в словаре вообще нет слов. Так можно повторять сколько угодно раз подряд.
- **Линейный проход:** в рамках одной сессии слово не повторяется (храним показанные
  `seenIds` и исключаем их из выборки — due-фильтра, на который раньше опирались, нет).
  Каждый новый `/repeat` стартует с чистого листа.
- **Вся сессия — ОДНО сообщение** (как в добавлении): правится по шагам через
  `editMessageText`, чат не засоряется. Первая строка — счётчик шага `N/total`.
  Ответ СКРЫТ, но нативный спойлер НЕ используем: Telegram не сбрасывает раскрытый
  спойлер при редактировании сообщения, и он «протекал» бы на следующие карточки —
  поэтому английского просто нет в тексте, пока не нажмёшь кнопку. Скрытая карточка —
  русское слово (+ русский пример как подсказка):
  ```
  1/9
  дом
  Пример: Мой дом большой.
  ```
  Кнопка **«Показать ответ»** правит то же сообщение, дораскрывая английский:
  ```
  1/9
  дом — house
  Пример: Мой дом большой. — My house is big.
  ```
  Кнопки: **«Показать ответ»** + **«Помню» / «Не помню»** (оценить можно и не
  раскрывая — как раньше с тап-спойлером).
  - «Помню» → интервал растёт по лестнице, `next_review` отодвигается.
  - «Не помню» → интервал сброшен, слово вернётся завтра. Повторно в этой же
    сессии не показываем (линейный проход).
- По нажатию то же сообщение редактируется на следующее слово. После последнего
  шага сообщение просто **удаляется** — ничего не остаётся (to-do §UX).
- **Коллизия:** в режиме REVIEW любой текст — шум (карточка уже на экране в том
  самом сообщении), поэтому мы НЕ шлём ничего нового, а удаляем присланный текст,
  чтобы не засорять чат; добавлять слова во время повторения нельзя (to-do §UX).

## 6. Флоу: тестирование

- **Запуск:** только по кнопке меню (без авто-расписания).
- **Направление:** всегда RU→EN (показываем русское, ждём печатный английский).
- **Выбор слов:** слова, которые сейчас НЕ due (`next_review` в будущем —
  «припаркованные как знаю»). Порядок — по `last_tested` по возрастанию
  (никогда-тестированные → давно тестированные), а внутри группы (вторичный
  ключ) — по `next_review` по убыванию: слова с самым далёким `next_review`
  первыми (идём от самых давно/много повторённых к недавно повторённым). Так тест
  аудирует то, что отмечено «Помню», и ротируется по всему выученному.
  Сортировка: `ORDER BY last_tested ASC NULLS FIRST, next_review DESC` (+ `id` для
  детерминизма). Выборка **снапшотится на старте** (апдейты `last_tested` по ходу
  иначе переупорядочили бы её). Если подходящих слов нет — тестировать нечего,
  сообщаем явно (тест, в отличие от повторения, доступен не всегда).
- **Размер:** отдельная настройка, дефолт 10.
- **Одно сообщение на сессию** (как §4/§5): вопрос за вопросом правится один
  `editMessageText`, ввод юзера удаляется. Первая строка — счётчик `сделано/всего`
  (**0-based**: карточка может пересдаваться в цикле, поэтому честнее «сколько
  закрыто», а не «номер шага» как в линейном §5, где счётчик 1-based). В отличие от
  §5, финальное сообщение **НЕ удаляется** — остаётся **итог со счётом** (и списком
  ушедших на повторение): это результат, который должен оставаться в чате (§UX).
- **Грейдинг — детерминированный, без LLM:**
  - нормализация: lowercase, trim, схлопнуть пробелы, срезать ведущий артикль
    (a/an/the), срезать ведущее «to» у глаголов;
  - верно = нормализованный ввод совпадает с ответом карточки;
  - синоним (не сам ответ) → неверно; опечатка → неверно; пропущенный артикль/`to`
    → прощаем.
- **Верно** → `next_review` не трогаем, обновляем `last_tested`; **авто-переход** к
  следующему слову (лишних кликов нет).
- **Неверно** → правильный ответ показываем **на той же карточке** («❌ Не правильно.
  «слово» — «ответ»») с кнопкой **«Дальше →»**; `next_review` сброшен (уходит в
  повторение), обновляем `last_tested`. По «Дальше» слово уходит в конец цикла на
  пересдачу (учебный режим — учим, а не экзаменуем). Пустой/пробельный ввод и
  кириллицу не грейдим — переспрашиваем на той же карточке (⚠️-пометкой).
- **Аварийный выход:** одна кнопка «Показать ответ» → раскрывает ответ **на той же
  карточке** («Ответ: «слово» — «ответ»») + «Дальше →»; провал (сброс `next_review`),
  по «Дальше» слово выходит из цикла (не пересдаётся). Так ответ всегда виден перед
  уходом — даже у последнего слова (а не «прыжок сразу в итог»). Показ ответа =
  пропуск, отдельной кнопки «Пропустить» нет.
- **Цикл:** когда запланированные слова кончились, неправильные присылаются
  повторно, пока на все не дан верный ответ (с доступным аварийным выходом).
- **Коллизии:** русское слово в тесте → валидация «только на английском», ждём
  новое сообщение.
- **Таймаут сессии:** 20 минут с последнего сообщения → сессия закрывается,
  недоотвеченные слова не затронуты.

## 7. Расписание / SRS

- У каждого слова: `next_review` (дата), `interval_index` (позиция на лестнице),
  `last_tested`.
- Новое слово → `next_review = завтра`, начало лестницы.
- «Помню» (повторение) → `interval_index++`, `next_review = сегодня +
  ladder[interval_index]`.
- «Не помню» / провал теста → `interval_index = 0`, `next_review` в ближайшее.
- Верный тест → `next_review` без изменений, только `last_tested`.
- **`next_review` — это приоритет, а не «допуск».** Чем меньше `next_review`, тем
  «созрелее» слово. **Повторение** берёт N слов с наименьшим `next_review` (без
  условия `<= сегодня` — оно для выборки бессмысленно: повторять можно всегда).
  **Тест** берёт `next_review > сегодня` (припаркованные «как знаю»). `next_review`
  в прошлом — норма (слово давно ждёт повторения), спец-обработки нет.
  - Нюанс: `due` НЕ используется планировщиком — плановое повторение шлётся ВСЕГДА
    (раз в день во `review_time`, если колода непуста), ровно как ручной `/repeat`,
    без условия «есть что-то просрочено» (см. §5; нет due → ревьюим самые «созрелые»).
    Опционально `due` мог бы пригодиться для cram-защиты в апдейте; сейчас простой
    режим: апдейт всегда двигает расписание (и наперёд тоже).
- Новый `next_review` всегда считается **от сегодня** (`сегодня + ladder[...]`),
  не от старой даты — просрочка не накапливается (пропустил неделю — слово не
  «улетает» дальше по лестнице).
- Гранулярность — дата в таймзоне пользователя (та же TZ, что у времени
  повторения); тай-брейк среди одной даты — по `created_at`. Технически даты —
  строки `YYYY-MM-DD` (под колонку `date`), арифметика календарная: `todayInTz`
  («сегодня» в TZ юзера) + `addDays` в UTC, без JS-`Date` в локальной зоне сервера
  (`src/lib/dates.ts`).
- **Лестница** — конфигурируемый массив дней, дефолт ≈ `[1, 3, 7, 14, 30, 60,
  120, 240]` (Anki-тип, ~×2 с затуханием); подкрутим на реальных данных.
- Выученные слова получают большие интервалы → выпадают из повторения, всплывают
  только в тесте (естественный «выпуск», отдельный архив не нужен).

## 8. Состояния и коллизии (на пользователя)

FSM: **IDLE/добавление → REVIEW → TEST**.

- Добавление работает только в IDLE; в REVIEW/TEST текст трактуется по контексту
  режима. Реализация — предикат `freeTextIn(mode)` (`src/context.ts`): текстовые
  хендлеры фильтруются по `session.mode` и **исключают команды**, поэтому
  `/`-команда никогда не перехватывается текстовым обработчиком чужого режима.
- Авто-повторение во время теста → откладываем, запускаем после завершения/
  таймаута теста. Тест за «сегодняшнее повторение» не считается и его не отменяет.
- Русское слово в тесте → «только на английском».
- Любое сообщение в REVIEW → повторно присылаем текущую карточку; добавлять слова
  во время повторения нельзя.
- Таймаут теста — 20 мин.

## 9. Настройки и меню

**Настройки:**
1. Количество слов на ежедневное повторение (потолок = размер колоды).
2. Время ежедневного повторения.
3. Количество слов на тест-сессию (дефолт 10).

**Реализация (Фаза 6):** меню — **одно редактируемое сообщение, чисто кнопочное и
БЕЗ состояния** (в отличие от review/test оно не держит сессию): каждый экран
(главный / редактор счётчика / выбор часа) — чистая функция от строки `settings` +
размера колоды; под-экран закодирован в callback-данных (`set:*`), id сообщения
берётся из самого callback'а. Поэтому новый режим в FSM не нужен, и панель
переживает рестарт (терять в памяти нечего).

- **Кол-во на повторение** редактируется степпером `±1/±5`; на экране — ЭФФЕКТИВНОЕ
  значение `reviewSessionSize(stored, deck)` = ровно столько слов запустит сессия
  (потолок = колода, §7), так что меню не расходится с планировщиком/`startReview`.
  Шаг считается от эффективного значения, поэтому no-op на потолке не перезаписывает
  хранимое (дефолт переживает рост колоды).
- **Время** — выбор только ЧАСА (сетка 6×4, 00–23); минуты пришпилены к `:00`.
  Планировщик технически поддержал бы минуты — гранулярность это решение UI.
- **Кол-во на тест** — степпер `±1/±5` в диапазоне `[1, 50]`; привязки к колоде нет
  (пул теста — подвижное not-due подмножество, рантайм всё равно берёт `min`).
- Валидация (`>= 1` и потолки) — клэмпинг в чистом `lib/settings`, значение валидно
  по построению. `timezone` из меню НЕ правится (env-seeded, см. ниже).

> Таймзона владельца пока задаётся через env `OWNER_TZ` (single-user, временно) и
> сеется в `settings.timezone` при провижининге. Правильный путь — 4-й пункт с
> выбором TZ из меню (см. `known_issues.md` №6).

**Меню действий** (через `setMyCommands`; опц. постоянная reply-клавиатура):
- Тестирование
- Повторение
- Настройки

## 10. Жизненный цикл слова

- **Правка** перевода/сета и **удаление** слова. Эта же правка — механизм
  бэкстопов, которые мы заложили: (1) починить неверный перевод/пример от словаря
  или LLM (в т.ч. фоллбэк-слова); (2) убрать лишний смысл из сета ответов (кейс
  омографа «замок» — оставить только нужное значение). Отдельных фич под бэкстопы
  нет — всё делает один флоу редактирования слова.
- **Выпуск** — не отдельная фича: большие интервалы сами выводят слово из
  повторения в тест.

## 11. Набросок схемы БД (предварительно, финализируем на этапе бойлерплейта)

- `users` (id, tg_chat_id, created_at)
- `settings` (user_id, review_count, review_time, test_count, timezone)
- `words` (id, user_id, russian `text`, english `text` — один ответ,
  example_ru, example_en, next_review `date`, interval_index `int`,
  last_tested `timestamptz`, created_at). Провенанс перевода (fallback/словарь) —
  флоу-онли маркер на добавлении (нудж «проверь»), в БД НЕ хранится: после сохранения
  карточка подтверждена юзером, а пост-сейв поле никто не читал.
- состояние сессий — grammY `session`, **только транзитивное состояние флоу**
  (`mode`, очередь карточек), in-memory: сбрасывается на рестарте — это желаемое
  поведение. Персистентные данные — только в таблицах выше.

Все таблицы с данными — с `user_id`, все запросы фильтруют по нему.
