# Known Issues / Отложенные решения

Осознанно отложенные проблемы и известные риски. Каждый пункт — решение «пока не
делаем / приняли риск», а не баг. Пересматривать по мере появления реальной боли.

## 1. Слипание интервалов повторения («лавина»)

**Суть:** слова, добавленные в один день, идут по лестнице интервалов пачкой
(1, 3, 7, 15…) — то густо (много due в один день), то пусто.

**Почему отложили:** для одного пользователя с умеренным темпом перенос остатка
сессии на завтра — достаточный клапан (reviews-first бюджет N, дни отдыха и сигнал
«не успеваешь» из §5 усиливают его).

**Путь решения:** джиттер интервалов ±10–15% (аналог «fuzz» в Anki) — слова,
добавленные вместе, разъедутся во времени.

## 2. Омограф словаря — РЕШЕНО (разбиением по `tr`)

**Суть (была):** омограф «замок» (castle / lock) мог сохранить оба перевода в один
сет → повторение ложно приняло бы и castle, и lock.

**Подтверждено живьём:** Yandex отдаёт «замок» одним `def` с двумя `tr`
(`castle` fr=10, `lock` fr=10).

**Решение (в коде):** маппер делит смыслы по **`tr`**, а не по `def` — каждый
перевод становится отдельным выбором (1. castle — дворец / 2. lock — …). Плюс
карточка хранит ОДИН ответ (синонимы `tr.syn` не берём). Так оба значения
физически не попадут в одну карточку — лечится самим выбором смысла, а не правкой.

## 3. ToS Yandex Dictionary

**Суть:** бесплатный ключ Yandex Dictionary — условия скорее некоммерческие /
с атрибуцией. Для личного бота ок.

**Путь решения:** перечитать соглашение перед переходом в мультиюзер/коммерцию.

## 4. Дубликат при двунаправленном вводе

**Суть:** добавив «собака» (RU), а потом «dog» (EN), можно завести дубль одной
пары. Перевод не всегда обратим — надёжного кросс-дедупа нет.

**Почему отложили:** низкая частота, низкий вред (ну две карточки).

**Сделано (мягко):** на добавлении проверяем по русскому промпту и показываем
существующую карточку («возможно, уже есть: дом → house»), но сохранить не мешаем.
Надёжного кросс-дедупа (перевод не всегда обратим) по-прежнему нет.

## 5. Непроверяемость фоллбэк-перевода редких слов

**Суть:** слова, которых нет в словаре, переводятся резервным источником (LLM).
При добавлении показываем «автоперевод, проверь», но редкое слово пользователь,
который его учит, толком не верифицирует.

**Принятый риск (повторяем фоллбэк наравне со всеми):** возможно-неверный эталон
попадает в повторение — может зря засчитать «неправильно» либо закрепить неверный
перевод как верный. Сознательно приняли ради простоты; смягчение — правка слова по
факту обнаружения.

**Почему так:** неустранимая часть задачи — ни один источник не покрывает всё;
честный путь — пометка «автоперевод, проверь» при добавлении.

## 6. Таймзона владельца задаётся через env, не из меню

**Суть:** `settings.timezone` нужен всей дата-логике SRS (расписание, «сегодня» в
TZ юзера). Сейчас задаётся только через env `OWNER_TZ` и сеется в `settings` при
провижининге. В меню настроек (§9) пункта TZ нет.

**Почему так:** single-user, временное решение (вариант A); меню настроек — заглушка.

**Путь решения:** 4-й пункт в §9 — выбор TZ per-user из меню. Тогда env становится
лишь дефолтом-seed, а источник истины — `settings.timezone` (важно для мультиюзера).
